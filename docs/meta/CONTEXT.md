# Çarshia — meta glossary

This is the project's *meta* glossary — the language used to talk about
the boilerplate itself: how the scaffold step works, what gets filled,
what stays fixed, where the design system substrate lives.

For the *storefront's* domain glossary (the brand voice, color roles,
visual mechanisms of whichever brand currently occupies the repo), see
the root [`CONTEXT.md`](../../CONTEXT.md).

## Language

### Process terms

**Scaffold session**:
One run of `/scaffold-storefront @handle` in a Claude Code session, from
clone to running dev server. Each session produces one storefront from one
IG handle. There is intentionally a human in the loop — the session is not
a headless CLI.
_Avoid_: "build", "generate" (under-specify — both could mean a CLI invocation
or a build step; "scaffold session" makes the in-the-loop nature explicit).

**Slot**:
A named, pre-defined placeholder in the boilerplate template that the
**Scaffold session** fills — palette tokens, wordmark, hero copy, seed
products, brand voice description. The skill never edits arbitrary code; it
only fills slots. New slots are added by editing the template (a real PR),
not by the skill at runtime.
_Avoid_: "config", "variable" (both imply key/value; slots are heterogeneous
— some are CSS tokens, some are full prose paragraphs, some are arrays of
seed records).

### Catalog seeding terms

**Showcase post**:
An IG post the **Scaffold session** classifies as catalog-eligible — a
product hero shot, a lookbook entry, or a menu item (archetype-dependent).
Seeds one row in the catalog. The classification rule is part of the
**Archetype** spec, not the skill itself.
_Avoid_: "main post", "real post" (both loaded and under-specifying).

**Context post**:
An IG post the session classifies as *not* catalog-eligible — atmosphere,
process, team, event, customer shots. Skipped from the seed catalog but
its image may still be used in non-catalog slots: hero photography, the
artisan-story band, the about page. The classification is *catalog-eligible
vs atmosphere-only*, not *keep vs throw*.
_Avoid_: "side post", "garbage post" (treats them as discardable; they're
not).

### Design system terms

**Archetype**:
A pre-built, coherent design language shipped in the boilerplate under
`template/themes/<name>/`. The **Scaffold session** picks one per scaffold
based on IG vibe; it does not invent design languages. Examples:
`heritage-artisan` (Cormorant + gilt-rule + cream/gold/navy — dardania's
current voice, generalized), `modern-minimal`, `warm-bistro`,
`boutique-fashion`, `streetwear`.
_Avoid_: "theme" (ambiguous with **Theme tokens**); "template" (taken by the
repo-level template).

**Theme tokens**:
The concrete CSS variables (palette, fonts, radii, shadows, motion timings)
that result from picking an **Archetype** and parameterizing it with values
pulled from the IG handle — palette extracted from the profile picture,
optional typography sister swap, optional rhythm variation. **Theme tokens**
are unique per scaffold; the **Archetype** they derive from is shared
across many scaffolds.
_Avoid_: "design tokens" (under-specifies — these are post-parameterization,
not the archetype's raw values).

**Brand voice**:
The per-scaffold narrative + copy system written into the scaffolded
storefront's own `CONTEXT.md` — the equivalent of dardania's "Heritage
Gjakovë voice", but generated by the **Scaffold session** for this specific
brand. Distinct from **Archetype** (the archetype is the *visual*
substrate; brand voice is the *narrative* layer that sits on top).
_Avoid_: "tone", "messaging" (both under-specify; brand voice includes copy,
mythology, and the relationship between the brand and place).

## Relationships

- A **Scaffold session** picks one **Archetype** and produces a set of
  **Theme tokens** + a **Brand voice** that together fill all the **Slots**
  in the template.
- An **Archetype** is *invariant across scaffolds*; **Theme tokens** and
  **Brand voice** are *unique to each scaffold*.
- Adding a new **Archetype** is a real PR with design iteration — not
  something the **Scaffold session** ever does on the fly.

## Flagged ambiguities

- **What does "ready" mean operationally?** Working assumption: the
  **Scaffold session** ends with `pnpm db:migrate && pnpm db:seed && pnpm
  dev` running locally and a console pointer to `http://localhost:3000`.
  Deployment to Vercel is a separate, operator-driven step. Revisit if
  the deployable preview turns out to matter more than local dev.
- **What e-commerce surface does each archetype need?** Deferred until
  archetype #2 lands (per ADR 0005). Day-one `heritage-artisan` inherits
  dardania's full cart+checkout+orders+addresses+admin stack as-is.
- **Bilingual extraction.** IG captions are typically one language
  (often English or sq). The session must always populate both
  `messages/sq.json` and `messages/en.json` for product titles and
  descriptions — translating when the source language is one-sided.
  Spec'd in the skill, not an archetype concern.
- **What the IG profile picture becomes.** Multiple candidates: wordmark
  dot color source, fallback hero photography, about-page avatar. Day-one
  decision deferred to skill spec; expected: extract palette from it,
  use it as the wordmark dot, *not* as hero photography (heritage-artisan
  hero stays curated stock photography of the brand's place — Çarshia for
  Autentika, equivalent for other artisan brands).
